# 京都競馬AI｜ハイブリッド自己進化型モデル設計・実装必須仕様
確定日：2026-11-12
状態：ユーザー合意済み設計理念・実装必須。**実装完了・実データによる進化成功を意味しない。**

## 1. 設計理念
京都競馬AIは、既存モデルのパラメータや特徴量を改良する方式だけでも、新しいモデルを追加する方式だけでもなく、**両者を独立に試し、必要に応じて組み合わせ、同一の未使用データで評価・独立監査された優位な構成のみ採用するハイブリッド自己進化方式**を採用する。

AIが自律的に選択するのは、改良案・追加案・統合案の**研究・実験候補**であり、採用可否は独立したEVO-07認定で決まる。進化と称して無条件にモデルを書き換えない。認定されない場合の正解は、現行チャンピオンの維持である。

本書は既存のP1～P8、ALG-01～13、EVO-01～08、MVP-01～05、F01～F20および固定採点基準・順序を**変更しない横断的な追加必須設計**とする。旧公開アプリの構造を流用せず、既存開発ブランチの成果を再利用する。

## 2. 進化候補の四つの型
1. **MODIFY（改良）**：既存モデルの特徴量選択、重み、較正方法、条件別規則、許可されたハイパーパラメータを制限内で改善する。
2. **ADD（追加）**：新しい特徴処理や予測手法を独立したプラグインモデルとして追加する。既存チャンピオンには影響を与えない。
3. **ENSEMBLE（統合）**：認定済みまたは研究中の複数候補について、事前固定した方式・重みで合成モデルを研究する。組合せの無制限全探索は禁止。
4. **KEEP／ROLLBACK（維持・復帰）**：改善未証明、データ不足、劣化、整合性異常では既存認定モデルを維持する。採用後に独立監視で劣化が認定された場合、最後に安全認定済みのモデルへ復帰する。

※新規追加モデルは必ず**既存と共通の予測入出力インターフェース**に従う。モデル追加によってP1～P8全体を再設計しない。

## 3. 必要となる共通基盤
- **Model Registry（モデル版台帳）**：変更不可のモデルID、親モデルID、候補種別（MODIFY/ADD/ENSEMBLE）、特徴量スキーマとバージョン、コード／設定SHA256、学習開始・終了時刻、許可された入力データ、推論時点、認定状況、承認・撤回の根拠、直前チャンピオンを追記型に保存。現行モデル切替を監査証拠なしに許さない。
- **Predictor Interface（共通予測契約）**：モデル入力にはレース識別子、時点、特徴量の原本参照とSHA、欠損理由、馬番と枠番、取消・発売状態を含む。出力は馬連／枠連の全有効組合せ確率、確率整合性、モデル版、説明可能な特徴・信頼度。未来情報・事後最終オッズを発走前入力に混入させない。
- **Candidate Sandbox（候補生成隔離）**：EVO-02/08の弱点・意外性分析から改善仮説を生成。EVO-06は許可されたアルゴリズム種別、特徴量定義、探索範囲、計算量、メモリ、試行回数内だけ実験する。任意コード実行、自己コード直接改変、本番Tursoや公開mainの無断書換は禁止。
- **Independent Evaluation（独立比較）**：研究者と評価者を論理分離。研究用学習・内部検証・未使用時系列・採用後前向き評価を分離。チャンピオン／候補／単純基準を同じレース・同じ発走前原本・同じ凍結時点で比較し、Brier・対数損失・確率較正、的中率、馬連／枠連ROI、最大ドローダウン、取引回数、見送り判断、データ欠損率・多重比較の影響を確認する。わずかな差や単発高配当を理由に採用しない。
- **EVO-07 Adoption Gate（独立認定とモデル切替）**：事前固定した母数・閾値・根拠・多重比較調整を満たす場合のみ採用候補を認定。認定・保留・拒否・証拠無効・認定取消を区別し、すべての版と判断を追記証拠で保存する。実用モデルの切替は当該環境の接続と承認済み運用条件の独立受入後のみ。実用未認定の間は研究影モードで止める。
- **Forward Monitor（劣化監視・復帰）**：認定後も新しい独立した開催日の予測・公式払戻・予測誤差を監視。性能の悪化、データ品質の劣化、前提崩壊を検出したら安全なチャンピオンへ戻し、判断・前後版・監査原本を残す。
- **P8 View（スマホ表示）**：現在のモデル、比較候補、改良・追加・統合・維持の理由、独立監査の状態、改善母数・期間・予測誤差・仮想収支・復帰履歴を研究／実用別に表示する。

## 4. P1～P8既定工程への組込位置
| 既存工程 | ハイブリッド自己進化に必要な実装 |
|---|---|
| P1 | モデル間で同時点・同一原本の比較が可能なデータ、欠損、SHA、取得時刻と履歴保管。EVO-01の追加データ価値評価。 |
| P2 | EVO-02・EVO-08で既存特徴の弱点、未知の相互作用、意外な結果と反例を継続検出。 |
| P3 | 共通モデル契約、MODIFY/ADD/ENSEMBLE候補、確率較正、モデル版・特徴量の互換性。 |
| P4 | 発走前に観測した馬連・枠連オッズを同一条件で評価。後出し価格は禁止。 |
| P5 | 同一日次予算・同一見送り条件によるモデルごとの配分とリスク比較。 |
| P6 | 研究用影モデルも同じ発走前原本で予測凍結。公式結果・払戻・返還・訂正を別管理し、事前登録の反実仮想を比較。 |
| P7 | 候補研究キュー、Model Registry、独立ホールドアウトとEVO-07監査、採否、劣化検知、ロールバック、再開可能な不変記録。 |
| P8 | モデル構成・版・採否・拒否理由・ひらめき・将来性能をスマホに表示。本番未認定時は実用進化を称さない。 |

## 5. 順序と最小受入ゲート（既存ゲートの内訳として実行）
1. P3/P7で**共通モデル入出力契約と追記型Model Registry**を実装し、既存P2/P3/P6/P7研究モジュールをアダプターで接続する。
2. **MODIFY**：制限されたパラメータ・特徴選択の改善案を研究環境で生成し、再現性・未使用データ・過学習防止・監査をテストする。
3. **ADD**：既存候補とは異なる新モデル部品を追加し、既存ベースラインと同じ原本・同じ期間で比較する。
4. **ENSEMBLE**：モデルの組合せ候補と新しい重みの比較を、事前固定した試行回数で実行する。
5. **P6/P7**で影予測の事前凍結→結果照合→候補評価→独立認定→チャンピオンの版切替・取消／復帰を一続きで検証する。研究用PASSを本番認定に流用しない。
6. **P8**でモデル版・監査状態・変更理由・研究と実運用の境界を表示する。

テストでは、未来情報混入、別時点／別レース比較、データ不足、同一結果で学習と独立評価、自己署名した偽造PASS、パラメータ暴走、無認定のモデル昇格、登録済み版の改変、再起動後状態欠落、劣化時復帰失敗、同一実験の二重処理、アルゴリズム組合せの過多を**拒否**すること。

## 6. 採用の証拠と未達の扱い
- EVO-01～08の**既存研究用統合・独立監査試験は成功**しているが、真正なJRA当日原本を用いた継続学習・独立進化認定・モデル自動切替・復帰は未実証。
- **次の11月14日公式データ取得を待たずに**、契約、版台帳、候補生成アダプター、研究モード比較、監査境界・安全な切替のコードと破壊試験は先に進める。
- 実際のP1→P6→P8ペーパートレードMVPを先延ばしにしない。実開催証拠が整った段階で研究機能と接続し、独立検証で初めて実用認定する。
- **固定指標を変更しない**：研究工程32/32=100%、研究卒業12/12=100%、主要機能21/21=100%、実開催接続0/6、実用能力0/100、最終20ゲート35/100。設計追記・研究fixtureの合格だけでは加点しない。
- main・本番Turso・公開Streamlit・Secrets・実購入経路は無断変更しない。既存の成功済みコード・証拠・保存済み原本を不必要に再実行・上書きしない。
