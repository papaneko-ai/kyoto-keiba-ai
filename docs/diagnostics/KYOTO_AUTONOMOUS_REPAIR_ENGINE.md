# 自動障害特定・修復の実装と継続工程
## 固定目的
未知の障害についても、失敗の保存、原因候補の探索、実証、修復候補の生成、独立検証、適用、再発確認まで自動化する。成功件数の報告のみで終了しない。未知の全種類の障害が必ず修復できるという保証とは区別する。

## 第1実装：公式PC/SPナビゲーションの構造変化
従来解析が失敗した場合、保存した原本からフォーム・リンク・ボタンと文字列アクションの組合せを探索する。従来の固定form ID、a要素onclick、固定空白配置と異なる組合せを実際のコードで回復する。DOM抽出と別の逐次HTMLスキャン、字句解析と完全一致正規表現の結果が同一の唯一の候補であることを要求。日付、京都、PC/SP、対象パス、フォーム、文字列以外の処理の拒否を維持する。候補を既存の通信制限内で適用し、原本SHA、規則SHA、候補SHA、照合結果を保存。保存原本から証拠を再計算し改変を拒否する。成功済みの既存経路は変えない。新規HTTPの追加、URL推測、JS実行、アクセス制限回避、資格情報変更、価格の推測はしない。

候補: f88f55c46ec03749dc71329abddb5c75f79d68a1。統合前試験 46106126008、統合版全793回帰試験 46106227647。既存夕方取得版と変更ファイルが重複しないことを確認して統合。未見のフォームID・ボタン・href・空白・文字コード組合せ、PC/SP実行経路、偽ホスト・別日・複数候補・余分な動作・証拠改変の拒否を試験。模擬の未知構造試験であり、明日の新規障害を既に観測したものではない。

## 拡張対象（未完成）
任意の未知コード欠陥、出馬表・プロフィール・両市場・馬場・結果払戻・調教の未知スキーマ変化、起動不成立、実行環境全損、外部システム停止に対する自動原因確定・修復は未完成。失敗を診断台帳に残し、修復可能な問題から同じ独立検証付き探索方式を拡張する。新規コード生成・変更を自動で行う汎用修復エージェントは別工程として扱う。証拠不足、アクセス拒否、外部障害、候補矛盾を無理に解決済みとしない。次回前の修復には、失敗再現、候補比較、実データの独立検証、保護設定維持、回帰合格、採用後再検査を要求する。
