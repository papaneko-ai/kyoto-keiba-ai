## 固定の完了条件
1. 予定起動、外部起動、実際の実行ID、適用版、保存を区別。実行名だけで成功としない。未起動も障害候補。
2. 暗号化保存原本を再認証し、レース・馬番・データ種別・取得時点ごとに再検証。未知母数を0として埋めない。両市場の一方欠落を成功にしない。発走後の値を発走前扱いしない。
3. 既知の直接障害、根本原因未証明、上流停止に伴う二次欠落を区別。実際の失敗原本・実行ID・SHA256・UTCを再利用し、同根の条件・日付・pin・読取器・他の取得経路を一括探索する。
4. 最小再現を新しい回帰試験として固定し、独立検証・異常系・故意の破壊・全体回帰・本番差分と同一版照合を完了する。テスト件数だけで総合バグ修正完了としない。
5. 実データを失わず、取得可能な時間帯の処理を不必要に止めない。未知の構造変化の適応修復は証拠に基づく。任意コードの自動修復は未完成。外部サービス障害や失われた過去時点のデータを完全回復できる保証はない。
6. 固定25リスクと今回の障害台帳を照合し、未証明は未完とする。次回の取得前に原因・修正・検証・本番反映を残す。実取得から予測開発へ移る条件は、合意した全データ項目の実証に基づき別途判断する。
