# 京都競馬AI・G06/H02項目別ハイブリッド補完 組込み工程・恒久指示（2026-11-18）

## 位置付けと変更理由
ユーザー指摘（2026-11-18）を正式な開発是正事項として登録する。
G06一括取得器 `diagnostics/kyoto_g06_all12_capture.py` は既存の `capture_hybrid` を各レースで呼んでいるが、`capture_hybrid` は主に「一方のチャネルでレース単位の両市場取得が成功するか」を判定し、特定障害時だけ他方へ切替する。PCで馬連だけ取得し、SPで枠連だけ取得できた場合の**項目ごとの原本結合**は未実装であり、`OFFICIAL_LINK_NOT_OBSERVED` 等が補完探索の終了状態として扱われ得る。
これは承認済みの「PC/SP双方向＋不足項目の補完＋利用条件を満たす補助情報源」というハイブリッド構想に対する機能欠落。**取得失敗理由の記録は補完開始のための証拠であり、通常の処理終了条件ではない。**

## 正式追加タスク（新しい固定分母や認定ゲートを増やさない）
1. **G06-HYB-01 取得・欠測マトリクス**: 全12Rの出馬表、馬連、枠連、それぞれの詳細フィールドを分け、出典・原本URL・SHA256・UTC・時点状態・馬/枠/レース同一性を保存。成功・暫定不足・他経路探索中・補完済み・真正性衝突・最終欠測を区別する。
2. **G06-HYB-02 PC⇄SP相互補完**: PCで馬連だけ成功したら保存したままSPの**枠連のみ**補完。逆方向も同様。PCの成功だけでSP探索を禁止しない。SPリンクが欠けた場合は観測済み公式ナビを独立に探索（PCの文字列からSP URLを推測しない）。すでに取得・検証した項目の無意味な再GETを防ぐ。
3. **G06-HYB-03 補助ソース**: 公式二系統で必要データが不足する場合、独立確認できる公開URL・項目定義・使用条件・時間真正性・レースと馬の同一性を検証した候補だけを試す。JRA公式データと補助情報を区別し、未知の利用条件/有料制限を迂回しない。
4. **G06-HYB-04 受領証と回復**: レースごとの独立進行を維持し、部分成功は破棄しない。成功原本の再利用・待機中の探索・必要なら後続取得枠で再試行を行い、回数を恣意的な1回制限に固定しない（合法性・通信負荷・発売状態・発走時刻の条件を評価）。原因を記録するだけで停止しない。**全ての利用可能な経路と合理的な再試行を使った後**のみ最終欠測とする。
5. **G06-HYB-05 競合・時点照合**: 馬連・枠連の原本は別チャネルから取得可能だが、共通したレース・発売状態・取得時点の整合性を個別に検証する。異なる時刻のオッズを同時点の1スナップショットと誤表示しない。同じフィールドに値の衝突があれば根拠を比較し、無条件上書きしない。
6. **G06-HYB-06 独立検証**: PC完全成功、SP完全成功、PC馬連+SP枠連、PC枠連+SP馬連、PC/SP双方部分成功、PC/SPリンク欠落→ナビ探索、補助情報源経由、両系障害、未発売、締切、最終オッズ、同一性不一致、原本改ざん、HTTP拒否、再試行後成功、全12Rで一部失敗、重複取得回避を個別試験。実原本の再生試験と、Actions SUCCESS／Artifact／SHAの独立確認を必須。
7. **G07/G09/H03/H05 接続**: G07へ項目別原本・欠測/衝突受領証を接続。H03の公式SP全12R実観測を活用。H05でPC単独/SP単独/PC↔SP補完/許諾確認済み補助ソースありを同じ実原本条件で比較。G09で統合障害試験。最終的な実開催成功はG10/G11で独立判定。
