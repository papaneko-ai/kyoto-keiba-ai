# 京都競馬AI・券種拡張と無断制約防止の恒久設計合意（2026-11-18）

## 決定事項
- 現行実用化対象は**馬連・枠連**。OR（二者択一）だけを完成仕様とせず、**馬連のみ・枠連のみ・馬連＋枠連の同時評価／複合投資**を可能にする。標準は複合自動最適化。複合モードでも両券種の購入を強制せず、片方のみ・両方・見送りを許す。
- 将来の**3連複・3連単**、さらに他券種をモジュール追加できるよう、券種に依存しないデータ・予測・買い目・予算配分・仮想投資・結果照合の共通インターフェースを設計する。今すぐ3連複／3連単の実運用を完成させるという意味ではない。
- 市場データは券種別に発売状態、取得UTC、原本SHA256、時点、組番と順序、オッズを保持する。単一馬券種専用カラムやradioの排他選択をシステム制約として固定しない。
- 確率エンジンでは1・2着の順不同の馬連、枠番号による枠連、1～3着順不同の3連複、着順指定の3連単を別の的中条件で扱う。3連単には順序付き着順の確率推定・較正を要し、単純な馬連確率の転用はしない。
- 最適化は券種横断で、期待値だけでなく的中率、推定誤差、相関による重複リスク、1日予算上限、損失管理、100円単位、見送りを考慮する。買い目数や推奨レース数の既存目安を機械的な機能排除に使わず、必要な変更は比較検証で決める。
- 実開催の発走前凍結→仮想投資→公式結果照合を優先。未検証券種の有効化はせず、将来拡張のための大規模な先行開発でG06・H03・P1～P8の進行を遅らせない。
- 合意済み機能を縮小する新たな任意制約を独断で追加しない。制約案には理由、失われる機能、代替案、解除条件、比較実験を明示し、機能縮小はユーザーの承認を得る。
- 法令・情報源利用条件、原本真正性、発走前後の厳密区別、本番環境／Secrets／Tursoの保全、予算上限は守る。架空データを作らない。

## 実装接続指示
1. **G06**: 馬連と枠連の両市場を同一レースで取得・保存し、共通MarketQuote / TicketCombination相当のモデルに載せる（将来券種追加可能な識別子と組番構造）。未発売・締切・最終を混同しない。
2. **P3/P4**: 券種別の的中条件、確率とオッズの結合をプラグイン可能にする。
3. **P5**: 馬連のみ／枠連のみ／複合自動の3モード。標準は複合自動。毎レース両方買う前提は置かない。
4. **P6**: 券種識別子、組番、予測時点とオッズ、凍結買い目、仮想投資、公式払戻の採点を券種横断で扱う。
5. **P7**: 券種・戦略の追加は時系列で独立検証し、性能劣化はロールバック。
6. UIの排他radioは暫定表示と位置付け、完成仕様にはしない。3連複／3連単は無効化された将来モジュールとして設計上の余地を残す。
7. **H03と11/21・22本番取得経路はこの文書の記録だけでは変更しない**。本番投入は別途実証後に行う。
