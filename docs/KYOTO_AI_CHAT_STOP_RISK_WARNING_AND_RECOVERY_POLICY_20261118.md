# 京都競馬AI｜チャット突然停止リスク対策・事前警告・復元規程
制定：2026-11-18（実装21）
適用：現行および将来の「京都競馬AI開発・実装NN」チャット
既存の `docs/KYOTO_AI_PERMANENT_RESEARCH_REUSE_AND_SECTION_HANDOFF_POLICY.md` を補完し、置換しない。

## 目的と限界
過去に赤色表示「このチャットではこれ以上会話できません」が突然現れ、継続会話・引継ぎ作業が困難になった再発リスクを軽減する。
ChatGPTの正確な会話残容量・残トークン数・停止閾値・プラットフォーム内部状態をアシスタントは直接取得できない。したがって「80%使用」等の偽りの数値表示・停止前の絶対保証は禁止。
GitHub Actionsはチャットの残容量を監視できず、チャット内アラートはアシスタントが応答できる時にのみ表示可能。停止後の警告送信も保証できない。

## 運用の二層化（バックアップとチャット移行を切り離す）
1. **作業状態の保存**：重要な実装・テスト・工程認定・外部設定変更の直後に、再開可能なGitHubコミット／検証結果・Run ID／次の再開コマンド／未完了事項／固定進捗を記録する。未コミット差分はチャットだけに残さない。
2. **復旧アーカイブ**：既存の `.github/workflows/kyoto-impl20-g06-checkpoint-archive.yml` を再利用する。既存の対象パスpush時・手動dispatchで最新3ブランチgit bundleと実験ブランチソースをArtifact化する。全pushで必ず起動するとは主張しない。重要な節目や終業時は実際のRun SUCCESS／Artifact存在／SHA／HEADを照合し、必要な時に既存workflowを手動実行する。Artifactの保管期限（現行設定90日）を永続保存と誤解しない。
3. **完全移行パック**：必要な節目、チャット移行、終業時に外部原本・既存蓄積資料も含むZIPと、同時点の専用開始指示書をセットで作成し、ダウンロード可能性を確認する。「ソースcheckpoint ZIP」と「完全移行ZIP」は同一ではない。
4. **新チャットから復元**：赤色停止の後は前チャットへの書き込みを前提にしない。直近完全移行ZIP、GitHub現HEAD、復旧用Artifactを新チャットで照合し、ZIP生成後のコミット・証拠を取り込んで再開する。既存成果を上書きしない。
5. **秘密情報・本番保護**：main、Turso本番、Secrets、11月21・22日取得予定、本番固定SHAを無承認変更しない。ZIPに含まれないSecrets値・TursoクラウドDB全量・外部タイマー状態は復元保証外。

## 会話停止リスクの注意喚起（作業中に実施）
毎回の重要な開発報告と、長いコード・ログ・添付ファイル処理後に、以下の観測可能な兆候をチェックする：
- 長大な入力・出力や大量のツール履歴が継続している
- 過去の合意・HEAD・進捗数値の参照漏れ、会話内容の取り違えが起きる
- 一回の作業で巨大なZIP・多数のログを繰り返し読み込む必要がある
- 実際のチャット画面に警告・継続不可表示が現れる（ユーザー報告）
観測可能な往復数は補助指標に限る。50往復程度から一段詳しく点検し、70往復程度から移行準備を検討するが、機械的に移行せず、データ量が大きければ早期警告する。これらの値は閾値の保証ではない。自動的にチャット全履歴を数えられない場合は数えたふりをしない。

### 通知レベル
- **通常（緑）**：直近復元点が検証済み、継続できる。必要がなければ通知を増やさない。
- **注意（黄）**：大きな会話量、長文集中など。次の重要な作業区切りで復旧状態を点検。**移行そのものを要求しない**。
- **準備（橙）**：参照漏れ、処理不安定、長文の著しい蓄積など。先に最新復旧点を保全し、可能ならZIPと全文指示書を事前作成。「次の安全な節目で移行を推奨」と伝える。
- **緊急（赤）**：実際の継続不能表示、復旧点欠落、チャット内文脈の重大な不整合。新チャット側でGitHub＋直近アーカイブから復元する。旧チャットへの追加操作を前提にしない。

通知には「観測事実／推定の限界／復旧点（HEAD・Run・Artifactまたは未確認）／次の行動」を含める。既存工程の進捗合格率とは混同しない。

## 安全な節目と続行の優先順位
移行するためだけに研究・実装を中断しない。ただし**未保存の重要差分のあるまま大規模な会話・ZIP解析を増やさない**。
重要変更コミット／テストSUCCESS／証拠レシートの保存を先行し、移行は節目の直後を第一候補とする。緊急時は節目途中でもチェックポイントを残し移行を提案する。
毎日の終業時点では、従来どおり最新完全移行パックと専用引継ぎ指示書を作る。

## 実装21に関する正本
作業基盤：`experiment/multisource-hybrid-20261117`。G06-HYB-01〜06項目別PC/SP/条件付き補助ソース補完が最優先。G06とH03・H05は未認定。11月21・22日実開催計画は保護。
本規程制定自体は、G01〜G12等の認定・固定進捗の数値上昇を意味しない。

## 実際にできること・できないこと
実施可能：各応答時のリスク判定と警告、GitHubに保存された正本からの復元、既存workflowによるソースチェックポイント、節目／終業時完全ZIP作成。
不可：ChatGPT内部の残容量を正確に計測すること、チャット画面を外部GitHub Actionsから監視すること、チャット停止後に同チャットから自動通知すること。
