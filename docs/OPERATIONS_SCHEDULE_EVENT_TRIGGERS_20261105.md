## 最重要原則
1. 毎レースのデータ追加・採点と、モデル再学習・本番昇格は別イベント。
2. JRA公開時刻には例外がある。固定曜日にアクセスするだけではなく「開催カレンダー・データ公開済み・レース確定」を状態遷移の条件とする。
3. 予測は必ず発走前の締切までにタイムスタンプ付きで固定。既に発走したレースは対象外。出走取消・発走時刻変更時は整合性チェック、必要なら予測保留。
4. 定期タスクの失敗は監査記録を残し、上限付き再試行。重複実行しても結果が変わらない冪等性と状態保存が必須。
5. データが不十分なら「取得待ち」「欠測」「予測保留」。架空値、結果の事前利用、予測日時の改ざんは禁止。

## 実行トリガーと処理

| トリガー | 推奨判定/ポーリング | 処理 | 成功条件 |
|---|---|---|---|
| JRA開催カレンダー検出 | 週初および開催前日（日本時間） | 対象開催日・開催場と全レース発走予定、例外開催を登録 | event_idと開催日、発走予定の照合 |
| 出走馬情報公開 | 木曜日16時過ぎを通常開始候補、特殊重賞は例外時刻を優先 | 出走候補・各馬の過去走・騎手/調教師履歴を取得、能力評価の初期版を計算 | JRA公式掲載の取得、馬ID突合、過去走時点制限 |
| 枠順公開 | 各レース前日10時過ぎを通常開始候補、GI等は例外 | 枠/馬番・頭数を確定してレース別の一次予測を再計算 | 公開済み枠順を確認、出走馬照合 |
| 当日馬場/取消情報公開 | 開催日朝と更新検知時 | 馬場・天候・取消等を差分更新 | 更新時刻と出所を記録 |
| 馬体重/事前オッズ公開 | 発走約60分前を起点に低頻度でチェック（変更あり） | 当日情報を反映、オッズと候補買い目を更新 | 「発表済」の実証、取得時刻の保存 |
| 予測締切 | **予定発走10分前を暫定設定**。実時刻の変更を検知し、安全側に更新 | 馬連・枠連推奨候補、確率、参照オッズ、仮想金額、モデルSHA、予測ログを不可変保存 | 発走前時刻の証拠。欠測なら見送り |
| レース確定・払戻公表 | レース終了後に確定状態を検知（単に入線しただけは不可） | 着順・払戻・同着・取消・不成立を公式から取得し、保存済みの予測を採点 | JRAの確定結果と突合、重複集計なし |
| 開催全レース採点完了 | 最終結果の確定後 | 的中率・回収率・損益・確率較正・予測漏れを集計 | 完了/未完了を分けた開催レポート |
| 週次・開催終了後 | 例: 月曜の日本時間、ただし変則開催なら最終開催日の翌日 | 条件探索の候補生成、特徴量候補の学習、過去学習期間の再構築 | 結果確定済みデータのみ使用。対象レース数を明記 |
| 月次・評価条件成立時 | 月初を点検契機、最小レース数・開催週数・未使用期間が揃ってから | モデル候補評価・採否審査、改善幅の検定 | 旧モデルと同じレース・買い目数・仮想予算で比較。条件未成立は保留 |
| 採用後の各開催 | 既存モデルと旧モデルを並走させる | 同じ発走前時点の予測を並走保存、確定後に双方を採点 | 旧新予測の事前登録が両方存在 |
| 成績劣化の監視 | 毎開催後+月次の安定性監査 | 悪化、欠測率急増、確率較正悪化を検知。警告→停止→復帰候補 | 不確実性を加味し標本不足は判定保留 |
| 代替進化の探索 | 新モデル不採用、劣化判定、または探索周期 | 別の特徴量・条件相互作用・学習器を候補として登録 | 新候補に新たな未使用評価期間が必要 |

## スケジューラの具体的な動作仕様
- 時刻帯は Asia/Tokyo を基準にジョブ設定。GitHub Actions cronはUTCのため変換と夏時間非該当を明示。cronは遅延・実行漏れがあり得るので**cronだけに依存しない**。
- 1日数回の低頻度起動で開催予定を確認。発走前の対象レースだけを期限付きキューに入れ、必要な時だけ追加取得。全レースのオッズを秒単位で連続取得する方式は採らない。
- ジョブ状態: EVENT_DISCOVERED -> ENTRIES_READY -> DRAW_READY -> PRE_RACE_INPUT_READY -> PREDICTION_FROZEN -> OFFICIAL_RESULT_READY -> SCORED -> ARCHIVED。中断時にここから再開。
- job_key=(race_id, stage, snapshot_type, version)。状態・試行回数・次回確認時刻・取得時刻・ハッシュ・失敗理由を保存。
- 予測締切後の市場オッズや馬体重は事前予測の特徴量に差し替えない。別時点の予測を行う場合は新しい予測IDと独立した締切が必要。
- レース終了後の「速報」を確定着順と誤認しない。審議・払戻発表まで待つ。確定結果の後日訂正にもバージョンを残す。
- スケジュールの健全性: 取得成功率、各段階の経過遅延、期限切れ率、予測保留数、的中率、仮想損益、旧新予測ログの欠損率を表示。
- コスト: GitHub Actions利用枠、実行回数、公式アクセス許容範囲を考慮。高頻度監視や大量一括取得は、負荷・規約確認後に段階的に実施。無料枠保証はしない。

## 選定・採用後のフィードバックループ
A 毎レース: 結果照合→採点のみ。学習データに追記し採用モデルは変更しない。
B 毎週: データ品質監査→有望条件の探索→**候補**モデルの訓練。失敗条件も記録。
C 十分な未使用期間・件数が揃った時: 候補のウォークフォワード+ホールドアウト検証。採用判定は既存ガードに従う。
D 採用後: 新旧モデルを各レースの事前情報で並走。悪化時は復帰できる状態を維持。旧モデルに戻しても過去ログは変更しない。
E 「進化した後に勝率が何%改善したか」は、両者が同一レースに予測参加した集合だけで表示。サンプル数、変化の割合ポイント、相対改善率を併記。券種別・出走数・仮想予算条件を固定。

## 重要な時刻の根拠と注意
JRA公式FAQによれば、通常は木曜16時過ぎに馬枠番号なしの出馬表、レース前日10時過ぎに番号付き出馬表。一部GⅠ・重賞で別時刻（木曜14時過ぎ、金曜9時過ぎなど）。
https://www.jra.go.jp/faq/pop02/2_2.html
JRA公式FAQによれば、馬体重は発表後速やかに出馬表へ反映。「発表済」を基準に検知。
https://www.jra.go.jp/faq/pop02/2_13.html
JRA-VANヘルプによれば通常発走約60分前に馬体重公開、例外あり。
https://support.jra-van.jp/jravan/detail?category=3&id=136&site=SVKNEGBV
JRAのルールによれば到達順位の表示→確定ランプ→払戻金発表。確定前に採点しない。
https://www.jra.go.jp/keiba/rules/kakutei.html
「予定発走10分前」は本プロジェクトの暫定設計値であり、公式規則ではない。実装の稼働試験で検証して変更可能とする。
