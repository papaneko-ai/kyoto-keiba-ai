# 京都競馬AI：PC/SP 実測・適応型取得経路選定マイルストーン（2026-11-06）

## 結論
**SP版を第1取得経路の「優先候補（CANDIDATE）」として診断環境で選定。ただし本番自動切替は未承認・未実行。PC版の正本取得経路は維持。**
選定根拠は、JRA公式の実HTML 5レース61頭の独立照合と、同一GitHub Actions実行環境でそれぞれ1回取得したPC版・SP版の通信および解析処理時間の実測。2026-11-07京都競馬の1R・5R・6R・11R・12Rを対象。オッズや当日の取消・除外を含めた完全なデータ同等性の証明ではない。

- 計測はPC・SP各5回のHTTP GET、各レース双方1回ずつ。最小1秒間隔、取得順序はレースごとに交互とした。全て前日2026-11-06に実行、翌日のレース情報を取得。
- 出走馬名・馬番・枠番の一致：**5/5レース、61/61頭**。新馬戦の5R・6Rを含む。JRAの非抽選馬等を出走馬として取り込まない。

## 取得経路選択の判定
`diagnostics/jra_source_router.py` の証拠優先ルーティングを使い、`diagnostics/jra_benchmark_acceptance.py` が保存済み5レースの実測JSON・全頭一致結果・改ざん検出用SHA・日時をチェック。
- 5レースが一致、実測5サンプルずつ、3レース以上の独立照合、15%以上のエンドツーエンド時間短縮 → **SP版を優先候補として提示**。
- 条件不成立の場合はPC版基準維持。不一致や時点ずれはRECHECKとして保留。
- SPだけ取得できる場合も、独立照合不足・取消/オッズ不明なら予測モデルへの採用は禁止。
- CANDIDATEは「本番に適用済み」を意味しない。今回のロジックは**オフライン判定のみ**で、データ取得先の本番アプリ自動切替・Turso DB書込みは一切行わない。
