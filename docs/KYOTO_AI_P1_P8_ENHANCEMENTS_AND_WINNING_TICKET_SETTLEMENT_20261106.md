## 3. レース直後の「当たり馬券」データパイプライン
1. **発走前スナップショット（不変）**：`prediction_id`、開催日・場・レースID、モデル版、券種(`QUINELLA`馬連/`BRACKET_QUINELLA`枠連)、正規化した組番、選択された買い目・各100円単位の金額、選択理由、予測的中確率、発走前オッズと原本SHA/取得UTC、仮想/実購入を区別する`ledger_type`。同一予測の更新禁止。
2. **結果専用の取得**：レース識別子に一致する公式結果の状態と着順、出走取消、除外、競走中止、同着、枠番、結果確定時刻、出所・原本SHA・取得UTCを別に保存。発走前特徴量へ流入させない。
3. **的中馬券・払戻専用の取得**：公式馬連・枠連それぞれの組番（昇順正規化）、**100円あたりの払戻額**、返還対象・発売状態、同着による複数的中組番、公式確定/訂正区分、取得UTCを保存。最終オッズを払戻金の代用にしない。
4. **照合**：`(race_id, ticket_type, canonical_pair)` で凍結済み買い目を公式の的中組番群と照合。該当券種が発売されなかった/返還となった券は`REFUND`として処理。的中券の払戻=`購入単位数×公式100円払戻`。不的中券の払戻0。複数組番的中・同着・同枠ゾロ目（有効な場合）を正確に扱い、同じ予測に二重計上しない。
5. **状態遷移**：`WAITING_FOR_RACE` → `RESULT_PRELIMINARY`（参考表示のみ）→ `RESULT_OFFICIAL_CONFIRMED`（着順確定・払戻待ちの場合あり）→ `PAYOUT_OFFICIAL_CONFIRMED`（ここで正式採点・収支確定）。取消／返還や訂正は別イベントで`OFFICIAL_CORRECTED`に遷移し、当該レースの集計を**再計算して置換**、差額を二重加算しない。取得失敗は`SOURCE_UNAVAILABLE`として保持し、前の確定値を消さない。
6. **取得タイミング**：各レースの発走予定時刻を手掛かりに、レース単位で公式結果を適切な頻度で確認。速報が見つかればアプリ表示に反映し、公式払戻が確認でき次第正式更新。**直後更新はベストエフォートであって保証ではない**。過負荷・利用条件に抵触しない間隔、上限、再試行、キャッシュ、アプリが閉じている場合の無料運用をP1で実証。実装方式未確定の段階で実行中と称さない。
7. **証拠保全**：出走前・速報・確定・払戻・訂正の各原本とSHA/UTCを別保存。重複イベントIDと版番号で冪等化。馬連/枠連の払戻が発表されていない場合は`UNSETTLED`、0円と決めつけない。

## 4. 用語と計算式（「勝率」の混同防止）
- **的中買い目率**＝`的中と確定した買い目数 / 判定対象の有効買い目数`。未確定・返還は分母から除外し別集計。計算対象に含める券種の指定と期間を固定。
- **的中レース率**＝`1点以上的中のあるレース数 / 有効な買い目を持ち判定完了したレース数`。複数点的中でもレースとしては1回。
- **回収率**＝`確定払戻総額 / 有効購入総額 ×100%`。返還は購入/払戻双方に入れる方式もあるため、ここでは**返還分を別計上・有効購入から除外**する基準を原則にし、表示文言・分母と常に併記。総資金の増減は`購入支出 + 返還 + 的中払戻`のキャッシュフローとして別途集計。 
- **損益**＝`的中払戻総額 + 返還総額 − 投入総額`。返還を的中とみなさない。
- **1着馬予測の勝率（単勝命中率）**＝`指定された1着馬予測が勝ったレース数 / 対象レース数`。この予測を事前登録していない場合は算出禁止。本アプリの主対象である**馬連／枠連の的中率とは別**。
- 的中率・回収率・確率較正は別指標。大数の法則・検証母数不足に注意し、小標本の高的中率を過大評価しない。買い目なしの見送りレースは別に予測評価する。

## 6. P6機能の受入テスト（まだ未実装）
- 馬連・枠連で的中／外れ／同着複数的中／同枠ゾロ目／発売なし／返還／取消／途中中止／誤組番／100円単位の金額不整合／未確定／後日訂正のテスト。
