## 1. 今回正式採用する6つの補強機能
| ID（新ALG番号ではない） | 名称 | 配置 | 期待する差別化 |
|---|---|---|---|
| EVO-01 | 賢いデータ収集／Active Feature Acquisition | P1、P2、P4 | 学習・公平な検証に必要な基礎データは全対象で維持し、**追加データだけ**期待情報価値と取得コストで優先順位付け |
| EVO-02 | 改善課題自動発見・優先順位付け | P2、P3、P7 | 距離・芝ダ・場・クラス・人気帯・馬場・展開・騎手等の誤差を分解し、次の最適実験を選ぶ |
| EVO-03 | 影のAI選手権（Champion–Challenger） | P3、P6、P7 | 現行候補、人気等の単純ベースライン、改善候補を同一条件で**発走前同時登録**し、仮想成績を公平比較 |
| EVO-04 | 反実仮想・投資戦略実験 | P4、P5、P6、P7 | 発走前の同一確率・オッズから2点/3点・均等/集中・見送り閾値などを**事前固定**して比較。事後の都合よい買い目選びは禁止 |

| EVO-06 | 自律進化型AI研究エンジン | P2、P3、P6、P7、P8 | 予測→公式結果→弱点発見→仮説→安全な候補生成→独立検証→採否→次開催の一連の閉ループを自動化 |

### 機能間の依存
- EVO-01は基礎データの網羅率を下げない。EVO-02/05で仮説を発見→EVO-06が候補実験を編成→EVO-03/04が凍結した発走前予測を複数検証→P6が公式結果と払戻で採点→P7が独立評価→合格候補だけ昇格する。
- **自動フィードバック（毎開催）と自動モデル昇格（検証ゲート合格時のみ）は別**。数レースの偶然や高配当一発でモデルを書き換えない。

## 2. P1～P8の既存工程に組み込む実装・受入条件
### P1（ALG-01,12）：時点と原本の堅牢性＋EVO-01
- レース／出走馬／馬ID・枠・オッズ・取消／除外・結果・的中組番・払戻のID、情報源、原本バイトとSHA256、取得UTC、モデル実行時点、版を分離保存。
- 学習用の**過去開催日横断**データについて、発走前に利用可能だった情報と結果後に初めて判明したラベルを列単位で明確に区別。結果後に取得した最終オッズを過去の購入時点に偽装しない。
- 「情報価値スコア」は`(未観測特徴による改善見込み × 不確実性) / (通信・保存・計算コスト)`等の**比較指標候補**。係数・採否は独立検証で決め、先に各馬の必須情報取得・既存P1完全性を満たす。
- 追加特徴ごとに`source_proof`、`available_at_utc`、`freshness_sec`、`missing_reason`、`cost_class`、`expected_value_of_information`、`leakage_status`、`acquisition_decision`を保持。未知・費用不明は安全側へ。
- **PASS**：同じ証拠から同じ収集候補順序が得られ、禁止URL・既取得URL・予測締切後の取得は0。取得優先度の変更によって学習/評価データの母集団を恣意的に間引かない。原本長期保存は別途検証。P1-FB双方向の本番自動切替は未認可のまま独立審査。

### P2（ALG-02,03）：自動弱点発見の入口＋EVO-02
- 勝馬／2着馬／敗退馬の母集団を期間、距離、馬場、コース、クラス、人気帯、休養、斤量、騎手／厩舎、脚質・展開で比較。相互作用や非線形効果を検証。
- 結果を見て作った「説明変数」は将来予測に使わない。低サンプル条件・多重比較による偶然の発見には**候補仮説**ラベルを付ける。
- レース単位のデータ構造を保ち、同一レースや同一開催日のデータが学習・検証へ混在しない時間分割を維持。
- **PASS**：説明変数生成の原本と計算過程が再現可能。検証期間外で同じ傾向が再現できない特徴は自動採用しない。

### P3（ALG-04,05,07）：確率品質の計測＋EVO-03の候補作成＋EVO-05
- ベースライン（市場支持率／単純人気等）、Harville、Plackett–Luce、Bolton–Chapman型、ベンター型、統計／MLハイブリッドは従来通り比較候補。モデル数が多いこと自体を採点しない。
- `p_first`、馬連／枠連`p_pair`、`calibration_version`、`uncertainty`、`confidence_basis`、`feature_missingness`、`training_cutoff`、`model_hash`を保存。券種の組合せ確率の合計・取消・同枠ゾロ目・同着/返還の扱いを検証。
- 劣化センサーの観測候補：Brier・対数損失、較正ズレ、人気帯別の過信、予測分布の変化、原本欠損率。**的中率だけで劣化を断定しない**。
- **PASS**：未使用期間で信頼区間・母数・較正を比較し、閾値は検証区間に後付けしない。感度分析と条件別サンプル不足を報告。

### P4（ALG-06）：期待値と当日変化＋EVO-04基礎
- **発走前の取得可能オッズ**と計算時刻を原本SHAで凍結。馬連・枠連の公式100円払戻は結果後の別ストリーム。直前のオッズ鮮度・取消・発売停止時は再判定し、使用禁止の古い見かけEVを排除。
- 反実仮想シナリオは**結果確定前**に`scenario_id`、券種、候補組番、参照オッズ、条件・評価規則を固定。結果後に勝ち券を選んで「仮想採用」を禁止。
- **PASS**：同じ事前スナップショットから候補全件を再現でき、最終確定オッズから事前スナップショットを再生成しない。

### P5（ALG-08）：投資/見送り最適化＋EVO-04,05
- 日次上限使い切り不要、原則2～3R最大4R、1R原則2点最大3点、100円単位、馬連・枠連の選択、手動配分と根拠、相関・最大損失・欠損時見送りは従来通り。
- 影の戦略として均等、集中、縮小Kelly候補、2点/3点、期待値閾値等を**事前登録**。比較には「同一モデル×複数購入戦略」と「同一購入戦略×複数モデル」の二軸を使い、予測品質と資金配分の効果を混同しない。
- 環境変化センサーが発報しても証拠不足なら即座にモデルを書き換えない。リスク側の保守的な縮小・見送りは既定の事前規則に基づく。
- **PASS**：見送りでも予想評価データを残す。架空のオッズ・市場データを生成せず、不明なら無推奨。

### P6（ALG-09,10）：公正な影AI選手権・反実仮想・公式自動採点＋EVO-03,04,06
- 発走前に**全候補を同時刻条件で凍結**。`event_id, race_id, prediction_id, model_id, model_version, model_hash, scenario_id, ledger_type, created_at_utc, odds_snapshot_sha, data_snapshot_sha, tickets, p_pair, amount, rank, skip_reason`等。何も買わなかった対象も分母・検証母集団へ。
- チャンピオン、人気等の単純基準、チャレンジャーの3系統程度を初期候補（数は検証で決める）。同じレース・同じ時点の入力情報・同じ券種・同じ予算制約で公平比較。条件に差がある場合は比較不成立。
- 公式結果速報→公式着順確定→公式馬連・枠連の的中組番/100円払戻金・返還→訂正を別イベントで取得。速報は仮判定だけ、公式払戻確認後に確定採点。原本・SHA・UTC・ID・取り込み版を保持し、誤払い・同着・返還・発売不成立、未確定を区別。
- `payout = stake_yen/100 × official_payout_per_100`（券種・組番一致の確定券のみ）、`profit = payout + refund - stake`、的中買い目率／的中レース率／回収率／最大ドローダウン／確率較正を別々に集計。仮想と実購入を分離。
- 同一結果100回再取り込み、再起動、公式訂正、通信断でも二重払いを防ぐ。モデル／戦略／母数／オッズ取得UTC付きの**改変不能に近いリプレイ台帳**と成績表が必要。
- **PASS**：すべての候補の`prediction_id`が結果前に存在し、結果後の有利な戦略選択が不可能。事後の勝ち組番への差し替え・同一予測の後書き禁止。無効な比較は成績ランキングに載せない。

### P7（ALG-07,11）：自律進化型AI研究エンジン本体＋EVO-02,03,04,05,06
**閉ループ：** `LOCK_INPUT → PREDICT_ALL → SETTLE_OFFICIAL → DIAGNOSE → PROPOSE_EXPERIMENTS → RUN_BACKTEST → HOLDOUT_COMPARE → DECIDE → MONITOR`。
- `DIAGNOSE`：レース/券種/芝ダ/距離/人気帯/不確実性/オッズ鮮度/馬場/展開で誤差、資金成績、見送り品質を自動分解。サンプル不足・欠損率・多重比較を監視。個別敗戦の原因を因果だと断定しない。
- `PROPOSE_EXPERIMENTS`：優先順位は**改善見込×証拠強度×評価可能な件数÷実験コスト**等の指標を候補とし、1回の実験予算・変更範囲・対象馬種・事前仮説・停止条件を固定。1開催ごとに大量の無制限探索を禁止。
- 生成できる候補（制約付き）：既存特徴の追加・除外、相互作用・重み、確率較正、モデル間アンサンブル、確率から買い目への変換、期待値/見送り閾値、配分比率、データ取得優先度。**自己コード改変・自動の本番設定変更・外部API増設・本番DB書換は禁止**。最初はホワイトリスト化した構造化パラメータ空間内の提案だけ。新規コード変更が必要ならPR/ユーザー審査。
- `RUN_BACKTEST`：学習期間内で探索し、未来時点のデータやレース結果を特徴に混ぜない。全候補の試行履歴・乱数シード・依存版・学習データSHA・モデルSHA・採否理由を保存。選択バイアスを含めて評価。
- `HOLDOUT_COMPARE`：学習・チューニング用検証・完全未使用の最終評価を**時間順に分離**。開発中何度も見た期間を「独立最終評価」と再使用しない。必要なら時間を前へ進めるwalk-forward検証。チャンピオン・単純ベースライン・候補を同一レースで比較。
- `DECIDE`：少なくとも①時点/ID/原本整合、②母数・欠損・確率較正、③比較指標（予測品質優先、回収率/リスク併記）、④多重比較への保守性、⑤追加コストと運用安定、⑥ロールバック可能性、のゲート合格が必要。**具体的な昇格閾値・最低サンプル数はP7でデータに先立って固定し、後付け変更禁止。**不合格なら`KEEP_CHAMPION`、暫定なら`CONTINUE_SHADOW`。すべての判断に理由コード。
- `MONITOR`：昇格後の劣化・データ品質悪化・ドリフト・損失規律・取得障害を条件別に監視。閾値超過で事前に承認された`PAUSE/REVIEW/ROLLBACK`のみ。チャンピオン変更の監査ログと前版復元手段を残す。
- **自動進化の解釈**：事前許容範囲での候補生成・影の評価・検証を自動化できる。**無制限の自己書換や、単一開催結果での無条件昇格は要件ではなく禁止**。ユーザー承認や安全なモデル切替権限の区別はP7/P8で設計・試験。
- **PASS**：同じ入力＋同じシードで再実行し候補・評価・採否が再現。全モデルが同一時点・同一対象。未使用最終評価で条件を満たさない候補は絶対に稼働化しない。ロールバックおよびシャドー継続をテスト。

## 4. 指標・モデル採用の誤解防止
- **勝馬予測の単勝命中率**と**馬連・枠連の買い目単位的中率／レース単位的中率**を混同しない。母数と券種・期間・モデル版を明記。
- `ROI = 有効的中払戻 ÷ 有効購入額`、`net_profit = 払戻 + 返還 − 投入`、確率のBrier/対数損失・較正、最大ドローダウンを併記。返還・未確定は別集計。
- 最も儲かった候補を結果後から選ぶ**事後最適化は禁止**。事前登録していないシナリオは正式な仮想成績に加えない。
- 「現行モデルを上回る」が意味するのは独立検証での**再現可能な品質改善**。期間短縮や見かけ高回収だけで証明しない。比較すべき競合予想サービスの性能データがない限り「競合より優秀」と主張しない。

## 5. 必須の故障注入・再現性試験
1. 発走後に取得したオッズ・結果が発走前特徴へ混入→拒否。
2. 人気等の基準モデルと候補で入力対象/対象開催日がずれる→比較拒否。
3. 原本SHA不一致・馬ID違い・URL推測・同一公式URL再GET→拒否。
4. 発走前に登録されていない当たり買い目を結果後に加える→拒否。
