# 京都競馬AI P1 広域節目：新開催日を指定できる公式市場取得経路と安全遮断（2026-11-10）

## 先行する正本と既存機能
KYOTO_AI_START_HERE.md、固定32条件の進捗台帳、前節目の保存済み3原本照合、既存 jra_one_shot_market_capture.py、jra_market_source_chain.py、jra_odds_matrix_parser.py を再利用。既存の2026-11-07固定11R取得実験は研究・過去の試験として保持し、同じロジックをゼロから作り直さない。

## 今回の広域到達点
- 既存ワンショット取得器に ObservedRaceSpec を追加。レース日、番号、ID、京都、PC/SPの実際に観測した公式出馬表URL、通常発売開始UTCを明示的に受け取る。旧既定設定は互換維持。
- 日付とレースID、URLの公式ホスト、HTTPS、accessD.html、CNAME構文、CNAME内の日付、PC/SPチャンネル、JSTでの発走日、通常発売開始時刻を検証。古い開催日のCNAME使い回しを拒否。
- 既存の発走10分前停止、未発売/最終オッズ拒否、取得した各レスポンスの時刻・SHA・バイト数、公式オッズ画面への観測済み遷移、両市場原本の独立検証を維持。出走馬重複も遮断。
- 実ネットワークは既定で不許可（LIVE_HTTP_NOT_AUTHORIZED、要求数0）。明示的なプログラム引数と外部許諾確認がない限り本番通信を開始しない。スタブ通信を用いた将来日パラメータの経路試験を実施。
- CLIに --race-spec-json を追加。新開催日向け設定を読み、実HTTPを起動せず検証・拒否レシートを残せる。推測CNAMEや日付を自動生成しない。

## 実際に未完了の外部依存
**この変更は新開催日のJRA実データを取得した証拠ではない。** JRAサイトの自動アクセスに関する利用許可と、対象日の実際に観測されたPC/SPの公式URL、独立に確定した発走時刻、取消・発売状態、発走前の馬連/枠連実HTMLを得られていない。JRAの許諾なしにネットワーク試行を増やしてはいけない。実ソースを得られた場合にのみ、前節目の保存済み3原本照合へ接続し、公式同定・時点・取消・市場フェーズを別々に受入判定する。

## 採点原則
固定P1-03（許容された新開催日のPC/SP自動取得）7点とP1-04（当日実発走前馬連枠連・取消・発売時刻原本）6点は未合格。研究用・安全試験の増加を加点しない。完成率31%、前回比0、残24基準を維持する。実HTTPは行っていない。main/Turso/Secrets/購入履歴は不変更。

## 再開時の具体的な受入順序
1. JRAの利用条件・取得許諾を確認し、根拠を保存する。
2. 対象日のPC/SP出馬表URLを公式画面から独立に観測し、race_spec.jsonへ入力する（推測CNAME禁止）。
3. 対象レースの発走時刻・取消・発売状態の独立根拠を固定する。
4. 許容された取得経路で発走前に公式3原本を保存し、各HTTP応答・UTC時刻・SHAを固定する。
5. 既存の3原本内容照合とsource chain、PC/SP代替を実原本で検証し、同一SHAのActionsログを確認する。
6. 上記合格まで予測・ペーパートレード実用判定・購入を禁止する。
