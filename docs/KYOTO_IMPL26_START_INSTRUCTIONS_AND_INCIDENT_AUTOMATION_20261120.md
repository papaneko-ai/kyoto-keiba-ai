1. **入力**：本番GitHub workflow_run完了、ジョブ/ステップ分類、暗号化Artifactの存否・原本の受領書・タイムアウト、予定枠の未起動（予約時刻を過ぎてもRunゼロ）。既存 `kyoto_impl25_c12_all_runs_handoff.py` とcross-slot inventoryを再利用。

3. **状態**：`DETECTED → EVIDENCE_LOCKED → ROOT_CAUSE_CANDIDATE → ROOT_CAUSE_PROVED → CANDIDATE_PATCH → OFFLINE_REGRESSION_PASSED → APPROVED_FOR_PRODUCTION → LIVE_RECHECK → CLOSED`。各遷移に判定証拠を必須とし、スキップは禁止。原因未確定/取得不能/翌開催待ちは `BLOCKED_WITH_REASON` を利用。
