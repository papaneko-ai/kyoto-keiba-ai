# 京都競馬AI｜アルゴリズム合意事項・保全台帳 v1.0（2026-11-06）

## 目的と保全方針
このファイルは、過去の会話で確認できた合意済みの目的・アルゴリズム・運用条件を消失させないための**実装基準**。別ファイル `docs/KYOTO_AI_ALGORITHM_AND_EXECUTION_ROADMAP_20261106.md` が順序・受入条件の工程表。本書の追記やバージョンアップは差分で行い、従来の合意事項を無断削除・矮小化しない。

**開発目的**：実データから好走・連対パターンを発見し、馬連・枠連の的中確率を較正したうえで発走前のオッズと比較し、期待回収率とリスクを総合してレース・買い目・金額・見送りを最適化する。発走前予測を変更困難な証拠として保存し、実結果による自動採点と時系列での新旧モデル比較により、検証された改善だけ採用する。通常の単純なChatGPT予測・単純人気順より有用な予測を目指すが、的中・利益を保証しない。

## 必ず保持するアルゴリズム要件
| ID | 機能 | 設計と検証の必須条件 | 現状 |
|---|---|---|---|
| ALG-01 | 事前時点の特徴量取得 | 過去走着順・着差・走破／持ち時計・距離・コース・馬場、斤量、馬体重、騎手、厩舎、調教、脚質、展開、枠順、人気、天候、馬場含水等。各値は原本・版・取得時刻と結び、発走後情報を排除 | 一部取得 |
| ALG-02 | 勝ち馬・連対馬の特徴自動発見 | 勝馬・2着馬・敗退馬の各母集団を比較。条件の組合せ・相互作用・レース種別の違いを分析し、未使用期間で有効な特徴のみ採用 | 未実装 |
| ALG-03 | コース・適性・展開評価 | 京都コース、芝／ダート／障害の区別、距離変更、直近成長、休養、脚質、先行馬密度、ペース、枠・騎手・厩舎相性を時系列で評価 | 基礎特徴のみ |
| ALG-04 | 確率予測モデル群 | 市場支持率・人気順ベースライン、Harville、Plackett–Luce、Bolton–Chapman型、ベンター型、市場情報併用の統計／機械学習モデルを比較。理論は検証候補で無条件採用しない | 未実装 |
| ALG-05 | 馬連・枠連の組合せ確率 | 1・2着の順序付き確率を合算して馬連へ。枠連は実際の有効枠組合せを集約し、同枠ゾロ目・取消・除外・発売停止を別処理 | 未実装 |
| ALG-06 | 市場価格・歪み・期待値 | 発走前の実オッズから馬連・枠連の期待値を計算。控除率／本命大穴バイアス／オッズ変動／情報鮮度／予測不確実性を考慮。過去の最終オッズを発走前とみなさない | 検証部品のみ |
| ALG-07 | 確率品質の定量評価 | Brierスコア、対数損失、較正曲線、期間・券種・人気帯ごとのサンプル数を確認。損益だけで予測品質を判定しない | 未実装 |
| ALG-08 | 資金配分・見送り | 1日予算は上限で使い切らない。原則2-3レース最大4レース、1レース原則2点最大3点。予測信頼度／データ鮮度／期待値／相関／損失リスクから順位と投資額を計算。縮小Kelly等は比較対象。100円単位と手動調整 | 未実装 |
| ALG-09 | 事前登録型仮想投資 | 発走前にモデル版・確率・レース順位・買い目・金額・時刻・原本とオッズを凍結、後変更不可。実購入・仮想収支を完全分離。買わなかったレースも評価 | 保存検証部品のみ |
| ALG-10 | 事後自動採点とリスク集計 | 公式結果・払戻を結果時点で取得し、的中率・回収率・損益・最大ドローダウン・較正・券種別の比較を自動計算 | 未実装 |
| ALG-11 | 学習・新旧モデル比較・自己進化 | 時系列で学習・検証・最後の評価を分離。旧モデル／新候補／シンプルなベースラインを同じ対象で比較。改善確認時のみ採用し、劣化なら却下・ロールバック可能 | 未実装 |
| ALG-12 | データ源とシステム最適化 | 公式PC・SPを正確性・項目完全性・取得速度・頑健性で比較。SP優位が確認できれば候補化。キャッシュ・通信制御・欠損時停止・原本／SHA／UTC管理。適法・無料を優先 | 診断のみ |
| ALG-13 | スマホUIと保守 | 初心者向け最小操作、内部分析は本格的。過去結果・仮想／実績・データ鮮度・推奨根拠を表示。業務用Work/Codexと混ぜない。後任にも保守可能 | 既存UIへ未統合 |

## 順序の固定
`P1` 事前予測用の情報確保・完全性・時点保証
→ `P2` 勝馬／連対馬の特徴発見と汎化検証
→ `P3` 確率モデル群の独立・組合せ比較と較正
→ `P4` 馬連・枠連の発走前オッズ・期待回収率
→ `P5` レース・買い目・資金配分・見送り
→ `P6` 時点固定仮想投資と公式結果自動採点
→ `P7` 新旧モデル同条件比較・改善確認後のみ採用
→ `P8` スマホ本番統合と無料範囲の保守。

※P4のデータ取得部分はP1と並行開発可能だが、予測と収支の正式採用は前段の品質ゲート後。

1. この台帳とロードマップを変更する際は、元ファイルを保持し、日付付きの新しい版を追加する。重要な合意の削除は明示的なユーザー承認を得る。
2. GitHubの診断用ブランチでだけ実験し、`main/app.py`、Turso本番・公開モデル・実馬券購入台帳を無断変更しない。
3. 各工程は必ず**実データ根拠、検証記録、失敗・欠損、次の未完了項目**を保存。CI通過と実性能は区別する。
4. 詳細原本の一部はGitHub Actionsの保存期限付きArtifactのみ。長期再現性の準備が完了したと誤認しない。
5. 外部データは公式・合法・利用条件順守・安定性・無料で可能な範囲を優先し、安易にスクレイピング制限を回避しない。
