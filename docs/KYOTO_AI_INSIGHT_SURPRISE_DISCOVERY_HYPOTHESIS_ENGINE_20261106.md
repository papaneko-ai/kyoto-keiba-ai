## 1．目的・既存正本との関係
- 人間の優秀な競馬分析家の「普通とは異なる好走条件を見抜く閃き」に相当する**機能**を、統計的仮説発見・反証・独立評価で実現する。単発の大穴や意外な勝馬から、確証のない法則を断定しない。
- 本書での機能名は **EVO-08「意外性発見・反証型仮説生成エンジン」**。この番号は既存のALG-01～13を変更・追加するものではなく、補強機能ID。既存EVO-02（弱点・研究課題発見）、EVO-06（候補生成と自律進化）、EVO-07（独立進化認定・監査）の横断的な能力として実装する。
- 既存P1→P2→P3→P4→P5→P6→P7→P8の順序を変更せず、**P2の仮説探索、P6の意外な結果に対する調査、P7の反証・独立検証、P8の研究レポート**に割り付ける。
- 同時に読む正本：`docs/KYOTO_AI_AUTONOMOUS_EVOLUTION_SIX_CAPABILITIES_REQUIREMENTS_20261106.md`、`docs/KYOTO_AI_INDEPENDENT_EVOLUTION_CERTIFICATION_AUDIT_20261106.md`、`docs/KYOTO_AI_VIRTUAL_INVESTMENT_AUTOMATED_FEEDBACK_PERMANENT_POLICY_20261106.md`。

## 2．具体的な能力
### A. 既存の常識を疑う（P2・EVO-02）
- 過去の一般傾向（例：特定距離の先行有利）を絶対視せず、距離・コース・馬場・枠順・展開・騎手・人気帯・クラス・休養などの条件で**効果が逆転する仮説**を探索する。
- 条件付き効果、交互作用、非線形性、階層的な差を比較し、単純な人気順・既存モデルのベースラインと照合。相関を因果と断言しない。
### B. 意外な組合せを見つける（P2・P7・EVO-06）
- 単独では弱い特徴でも、複数を組み合わせると連対予測・的中確率の改善に寄与するか仮説生成。
- 無制限な特徴量の組合せ探索を避け、探索対象・候補数・計算上限・条件最小件数を事前に規定。数が少ない特徴組合せには`EXPLORATORY_ONLY`。
- 候補の評価は**統計的支持、独立期間での再現性、データ取得コスト、予測時点の利用可能性**を別々に記録する。
### C. 意外な結果を重点研究する（P6・P7）
- 発走前の予測確率と実際の1・2着／馬連・枠連の公式結果との差から`surprise_score`を算出する。候補例：結果の予測対数損失、較正済み低確率事象、複数モデルの共通誤差、想定展開からの乖離。定義は独立検証の前に固定。
- 重要：**意外さの大きい単発事例は問題提起に使うだけで、学習に取り入れる法則の証明にはしない。** 過去の同条件の有無、逆例、欠損・誤ID、確率較正、当時のオッズ鮮度などを点検する。
- 的中したケースだけでなく、外れ、見送り、予想外の人気馬敗退、複数モデルが外した共通事例も研究対象とする。
### D. 発見を自ら疑う（P7・EVO-07）
- 発見仮説には**反証条件・確認すべき逆例・対象母集団・使用特徴・検証期間・事前固定の成功指標**をセットで登録する。
- 当該結果を見て生まれた仮説は、その結果・当該期間で「独立検証済み」と認定しない。将来の未使用期間または独立の別期間で検証する。
- 選択バイアス、データ漏洩、多重検定、低頻度事象の分散、過去との条件差、単一開催の偏りをEVO-07が検査。反証された仮説は履歴付きで却下。検証不能は保留。
- モデルへの取り込みは、EVO-07の独立認定ゲートとユーザーが定める採用権限の規則に従う。発見を理由に自己コードを書き換えたり本番DBを無承認更新しない。

## 3．保存する研究記録（候補スキーマ）
`DiscoveryHypothesis`：`hypothesis_id, generated_utc, triggering_race_ids, surprise_metric_version, baseline_model_hashes, conditions, interaction_features, hypothesis_text, null_hypothesis, falsification_rule, counterexamples, training_cutoff_utc, source_original_sha, sample_count, missingness, candidate_generation_config_sha, search_trial_id, status`。
`HypothesisExperiment`：`hypothesis_id, preregistered_plan_sha, train_period, tune_period, untouched_holdout_period, evaluation_code_sha, seed, candidate_model_sha, baseline_score, challenger_score, uncertainty_interval, multiple_test_adjustment, runtime_cost, source_sha, decision, decision_reason, evaluated_utc`。
状態：`OBSERVED_SURPRISE`→`HYPOTHESIS_PROPOSED`→`EXPLORATORY_TESTED`→`INDEPENDENT_EVALUATION_PENDING`→`SUPPORTED`／`REFUTED`／`INSUFFICIENT_EVIDENCE`。ここで`SUPPORTED`は候補仮説の支持であり、EVO-07の正式モデル昇格と区別する。

## 4．工程別の受入条件
| 工程 | 必須実装・判定の追加 |
|---|---|
| P1 | 特徴量の欠損・予測時点・公式結果と払戻の別管理。意外性判定の根拠となる原本SHA/UTCを保全 |
| P2 | 条件別の逆転・交互作用・意外な共通点を**候補仮説**として生成し、逆例と母数を併記 |
| P3～P5 | 確率・オッズ・見送りの標準指標を保持。予測時点に存在しない特徴から閃き仮説を作って採用しない |
| P6 | 発走前予測と公式結果の差から意外性スコアを計算し、外れ・見送り・モデル共通失敗を含め調査キューへ登録 |
| **P7** | EVO-06で制約付き仮説実験、EVO-07で未使用期間による反証・独立認定。偶然の発見を本番の自己進化と混同しない |
| P8 | 「AIが気づいた意外な傾向」「反証例」「検証待ち／支持／不採用」「次の実験」「採用の有無」を初心者向けレポートに表示 |

## 5．必須テスト（未実施）
1. 偶然の大穴的中1件→興味深い事例登録は可、進化認定は不可。
2. 全特徴の大量組合せから事後に最大得点だけ選ぶ→多重検定/新期間評価で拒否。
3. 意外な結果を見て生成した特徴を同じ結果で「予測成功」扱い→禁止。
4. 人気帯・馬場・距離別に評価対象が極端に少ない→`INSUFFICIENT_EVIDENCE`。
5. 意外な結果が公式確定前・誤馬ID・返還・取消・データ欠損由来→誤研究を停止／隔離。
6. 仮説支持後も将来評価で不安定→EVO-07の監査で昇格保留・必要なら降格。
7. 同一入力・シード・原本・実験計画で同じ仮説候補・判定が再現できる。
