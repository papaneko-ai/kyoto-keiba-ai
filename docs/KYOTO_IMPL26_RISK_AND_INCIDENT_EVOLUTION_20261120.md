## 最上位目的と完了の区別
1. 現時点で合理的に予見できる障害を**本番開始前に最大限減らす**。機能追加・資料作成・テスト件数の増加は目的ではない。
2. 本番の成果は実データ原本の **開催日×レース×全馬×データ項目×市場×取得UTC×SHA256** で定量判定する。CIが緑でも取得成功とはみなさない。
3. 既知リスク台帳の分母は **40件固定（R01〜R40）**。この分母の変更は定義変更履歴で明示し、進捗を勝手に上下させない。
4. 将来の未知障害は **INC-連番** で別台帳に無制限追加。40件の固定分母に混ぜない。R番号との対応付けと影響分析は必須。
5. 未知障害をゼロにできるとの主張はせず、発生後の**記録→同原因探索→修正→逆方向試験→独立証拠→運用採用**の循環を運用要件とする。

## 失敗の学習サイクル（固定）
**検知**: 実行枠開始・最終イベント・Run終了・欠測を観測。GitHub Actions successはデータ取得成功の代理指標にしない。
**記録**: 原本・Run/Job/Artifact ID・ステップ名・イベント予定UTC/実UTC・対象馬/市場/種類・エラー種別・原因候補・SHA/取得UTC・取得済みを保存。鍵・Token・個人情報・生の秘匿原本を公開しない。
**分類**: `NOT_TRIGGERED` / `PRE_HTTP_STOP` / `HTTP_FAILURE` / `PARTIAL_SAVED` / `SOURCE_BYTES_SAVED` / `STRUCTURED_FIELDS_VERIFIED` / `BOTH_MARKETS_VERIFIED` / `SEALING_FAILED` / `UNKNOWN`。各状態を証拠なしで昇格させない。
**原因特定**: 一次の現象と根本原因を分離。既存R01〜R40、過去のINCを照合し、同根本原因が他レース・他市場・別Run・PC/SPにないか検索する。
**候補修正**: source-onlyの隔離ブランチ。通信上限、データ鮮度、暗号化/Turso/Secrets、URL推測禁止の既存規則を保持。意味変更や本番DB変更は承認を要する。
**再現・回帰**: エラーを再現する模擬HTTP/時刻/中断/整合試験に加え、既存成功ケース・逆方向ケース・継続時の重複取得・原本保存を独立CIで検証。
**リリース**: 実行commitを固定し、CI・保護差分・バックアップ・戻し先を記録して本番参照を更新。22日変更は `KYOTO_NOV22_VERIFIED_COLLECTOR_SHA` の既存独立ゲートを通す。無承認の自動書換えは禁止。
**検証・再発防止**: 次の実データで同じ失敗の再発率と取得率を確認。失敗が続けば旧版に戻す。事後に原因と回帰試験を恒久的に保存する。

## リスク台帳の判定状態
- `MITIGATED_WITH_PROOF`: リスクごとの対策と独立再現/回帰証拠を確認。
- `LIVE_VERIFICATION_PENDING`: 机上対策あり、開催当日を待つ（未合格）。
- `OPEN`: 対策未完・再現試験不足。
- `ACCEPTED_WITH_REASON`: 現場の利用価値と安全上の理由を記録し、期限を付けて残余リスク受容。未対策の成功扱いはしない。
- `INCIDENT_ACTIVE`: 実故障を検知し追跡中。
